# Pre-implementation gate

`pre-implementation` gate выполняется перед изменением файлов.

Этот каталог хранит только общие pre-implementation проверки входного gate-а.
Domain-specific проверки могут жить в профильных owner-layer, например
`.ai/checks/development/` и `.ai/checks/development/frontend/`. State machine
не перечисляет конкретные проверки, чтобы не дублировать
`.ai/registry/rules/`.

## Назначение

- определить обязательные проверки перед правкой файлов;
- выбрать применимые checks по задаче, owner-layer и планируемым действиям;
- зафиксировать обязательный вывод до изменения файлов;
- остановить реализацию, если check не пройден.

## Порядок применения

1. Классифицировать команду как `dialog_only`, `simple_direct_step` или
   `managed_work_task`.
2. Для рабочего шага выполнить строгую проверку разработки:
   `.ai/checks/development/CHECK-DEVELOPMENT-STRICT-PRINCIPLES.md`.
3. Определить контур задачи, owner-layer и планируемые действия.
4. Открыть `.ai/registry/rules/INDEX.md`.
5. Найти активные правила, trigger которых подходит к задаче.
6. Открыть связанные `CHECK-*.md` по путям из `.ai/registry/rules/INDEX.md`.
7. Выполнить обязательный вывод каждого применимого check.
8. Продолжать реализацию только если все применимые checks имеют результат
   `passed`.

## Границы

- Этот INDEX описывает порядок gate-а, но не владеет всеми checks проекта и не
  дублирует полный текст правил.
- Каждый `CHECK-*.md` хранит собственные pass/fail conditions.
- Реестр хранит связи между rules, checks и ответственными ролями.
- История, причины появления checks и отчёты о событиях не хранятся в этом
  файле.

## Результаты

- `passed` - все применимые checks выполнены.
- `stop-for-approval` - требуется решение пользователя.
- `failed` - реализация запрещена до устранения причины.
