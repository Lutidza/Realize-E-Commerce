# Не переносить исторический шум в рабочие файлы

```yaml
rule_id: RULE-NO-HISTORICAL-NOISE
title: Не переносить исторический шум в рабочие файлы
owner_role: Владелец документации
applies_to:
  - все файлы проекта
  - активные исполняемые правила
  - проверки
  - рабочие процессы
  - артефакты адаптерного слоя Codex
trigger:
  - добавление исторического контекста
  - добавление отчёта о событии или обоснования в рабочий файл
  - перенос истории из диалога в контракт
  - добавление устаревших путей или следов прошлых ошибок
requirement:
  - держать рабочий файл в границах его актуального назначения
  - добавлять исторический контекст только если он нужен текущему назначению файла
  - выносить историю в корректный owner-layer, если она нужна, но не принадлежит целевому файлу
forbidden:
  - делать отчёт о событии, отчёт, черновик или предложение источником истины для рабочего файла
  - добавлять историю обсуждения как часть рабочего контракта
  - оставлять устаревшие пути, прошлые решения или следы исправленных ошибок
checks:
  - .ai/checks/pre-implementation/CHECK-NO-HISTORICAL-NOISE.md
related_codex_artifacts:
  - .codex/skills/skill-documentation-sync/SKILL.md
related_tools:
  - rg
escalation:
  - stop-for-approval: неясно, является ли контекст историческим шумом
```

## Контракт выполнения

Рабочий файл содержит только актуальное назначение, контракт, структуру,
правило или исполнимую инструкцию своего owner-layer.

Если исторический контекст нужен, но не относится к назначению целевого файла,
агент не добавляет его в рабочий файл и определяет корректный owner-layer
исторического артефакта.

## Термины

- Рабочий файл — любой файл проекта, чьё назначение не хранить историю, отчёт,
  журнал изменений, запись решения, запись памяти, артефакт запуска или историю
  реестра.
- Исторический шум — прошлые события, обсуждения, ошибки, временные решения,
  причины появления файла, устаревшие пути или следы исправленных проблем,
  которые не нужны для актуального назначения файла.
- Актуальное назначение файла — поведение, контракт, структура, инструкция или
  справочная информация, ради которой файл существует сейчас.

## Допустимые исключения

Историческая информация допустима, если файл по назначению является:

- отчётом о событии или ревью-отчётом;
- журналом изменений;
- записью решения;
- историей задачи;
- артефактом запуска;
- записью памяти;
- исторической записью реестра;
- заметкой о миграции, legacy-состоянии или текущем состоянии, если она
  описывает действующий контракт, ограничение или путь миграции.

## Матрица решений

- Исторический контекст нужен для актуального назначения целевого файла:
  оставить в целевом файле.
- Исторический контекст нужен, но не относится к актуальному назначению
  целевого файла: не добавлять в рабочий файл и определить owner-layer
  исторического артефакта.
- История используется только как объяснение причины появления правила, кода
  или правки: не добавлять в рабочий файл.
- Неясно, является ли контекст историческим шумом: остановиться и запросить
  решение пользователя.
- Контекст описывает действующий контракт миграции, legacy-состояния или
  текущего состояния: допустимо оставить как часть актуального назначения
  файла.

## Обязательный вывод

Перед добавлением исторического контекста в рабочий файл агент выводит:

```text
Проверка исторического контекста:
- целевой файл:
- назначение целевого файла:
- контекст:
- нужен для актуального назначения файла:
- требуется отдельный owner-layer:
- решение:
```
